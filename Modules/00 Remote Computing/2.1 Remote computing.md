
- Why use a remote computing system?
	- Memory and compute capacity far exceeds anything available commercially
	- Parallel computing capacity
- Most large-scale genomic algorithms are implemented in a command line, Unix environment
- Elements of remote comuting
	- Interacting with the cluster
		- Logging on
		- Preparing job scripts
		- Submitting jobs
	- Managing data between local computers and the cluster
		- Copying files
		- Retrieving data
		- Compressing data
		- Verifying data
## Using a remote computing environment
### Logging on
- The shell may take commands interactively entered and scripts
- To access the cluster, you need to create a shell on the cluster's environment
	- Default shell on Mac is `zsh`
	- Cluster uses `bash`
- `ssh` (`s`ecure `sh`ell) command is used to establish a secure connection
	- Ensures that data is encrypted
	- Requires password authentication

```zsh
ssh <username>@hpc-portal2.hpc.uark.edu
```
### Navigating the file system
- Upon logging on, users are located on the "head" or login node
	- The head node is responsible for organizing the activity of other nodes
	- You shouldn't send jobs directly to the head node, or else you might compromise its ability 

```bash
# log-in node
$ /home/<username>

# data storage
$ /storage/<username>
```

- The head node contains two subordinate nodes: 
	- compute nodes 
	- storage nodes
- There are two types of storage nodes:
	- The `/storage` node is designed for stable long-term memory and has high read-write costs
	- The `/scratch` node is designed for active use during a job, and has efficient read-write but isn't stable storage long term

```bash
# site of standard jobs
$ $HOME
$ storage

# site of jobs with high read/write
$ /scratch/$SLURM_JOB_ID
```
### Copying files to a remote computer
- Use the `scp` (`s`ecure `c`o`p`y) command to copy files between hosts on a network
- An `scp` command has the basic structure `scp [options] <source> <destination>`
	- A color separates the destination host ID from the destination filename

```bash
# Copying files between computers
scp [options] <path_to_file>/<filename> <username>@<destination_host>:<path_to_file>/<filename>

# Copying files to a remote computer
scp nad4.fasta aja@hpc-portal2.hpc.uark.edu:new_file.fasta

# Copying files from a remote computer
scp aja@hpc.portal2.hpc.uark.edu:nad4.fasta biol5153/watermelon_files/
```

- In the example above, the file `nad4.fasta` is copied to Dr. Alverson's storage on the HPC and saved as `new_file.fasta`
	- If you want to keep the same name, don't include anything after the `:`
- Shareware programs linke Fugu and FileZilla provide graphical user interfaces for `ssh` and `scp` commands
### Synchronizing directories
- `rsync` is used for synchronizing directories
	- It transmits the difference between file versions in a directory
	- Can compress files during transfer
	- Using the archive option, features like links, timestamps, permissions, ownership, and other attributes
- An `rsync` command has the following format: `rsync [options] <source> <destination>`
- `rsync` options include:
	- `-a` or `--archive` to preserve links, timestamps, etc...
	- `-r` or `--recursive` to recurse into directories
	- `-v` or `--verbose` to print verbose output during the synchro
	- `-z` or `--compress` to compress data as its sent to its destination
	- `-l` or `--links` to preserve symbolic links
	- `-e` to copy over SSH

```bash
# Synchronize a folder to your desktop
$ cd ~/Desktop
$ rsync -av <folder_to_sync> .

# Two distinct processes:
$ rsync -av ~/Desktop/watermelon_files/mt_genomes .
$ rsync -av ~/Desktop/watermelon_files/mt_genomes/ .
```

- A file path without a trailing `/` copies the entire directory, including subdirectories
- A file path with a trailing `/` copies only the contents of the folder without preserving its directory structure
### Compressing large files
- `gzip` is used for compressing, `gunzip` is used for decompressing
	- Operates on files in place by default; doesn't produce new files
		- Adding `-c` creates a duplicate file in STDOUT
	- Writes to STDOUT by default

```bash
# View a zipped file
$ zless <filename>

# View a zipped file
$ zcat <filename>

# grep a zipped file
$ zgrep <text> <filename>
```

### Creating archives 
- `tar` is used to create and manipulate `t`ape `ar`chives, which can be used to compress entire directories while preserving their structure
- A `tar` command has the structure `tar [options] archive directory`
- `tar` options include:
	- `-c` create new archive
	- `-x` extract an archive
	- `-v` produce verbose output
	- `-f <filename>` read the archive from/write it to the specified file
	- `-t` list archive components
	- `-z` compress the archive with `gzip`

```bash
# Archive and compress a file
$ tar -czvf <archive> <directory_to_archive>

# Extract and decompress a file
$ tar -xzvf <filename>

# View contents of a file
$ tar -tvf <filename>

# Extract a specific file from an archive
$ tar -zxvf <archive> <path_within_archive>
```
### Downloading data from the internet
#### `wget`
- `wget` is used for non-interactive file downloads (from ftp and http sources)
- A `wget` call as the following format: `wget [options] url`
- `wget` options include:
	- `-A` or `--accept` to accept files matching this criterion
	- `-R` or `--reject` to reject files matching this criterion
	- `-r` or `--recursive` to use recursive downloading
	- `--user=<username>` to give a username for password authentication
	- `--ask-password` prompt for password
	- `--no-remove-listing` to list directory contents without downloading

```bash
# Download human chromosome 22 from UCSC Genome Browser 
$ wget http://hgdownload.soe.ucsc.edu/goldenPath/hg19/chromosomes/chr22.fa.gz 

# Download all the GFF files from your colleague's server 
$ wget –accept "*.gff" --level 2 –r --no-directories --no-parent \ ftp://server.university.edu/labsite/annotations/ 

# Download from a secure ftp site 
$ wget ftp://<username>:<password>@192.169.8.66/folder 

# Download from a secure ftp site 
$ wget --recursive ftp://andy:run-dmc@192.169.8.66/CleanData
```
#### `curl`
- `curl` has a similar function to `wget` but has more protocols
	- Writes to STDOUT by default
- A `curl` call has the format `curl [options] url`
	- `-o` specifies the output file

```bash
# Download a protein structure from RCSB's protein databank 
$ curl "http://www.rcsb.org/pdb/files/1ema.pdb" 

# Write it to a file using -o option 
$ curl "http://www.rcsb.org/pdb/files/1ema.pdb" -o 1ema.pdb 

# Download a set of files 
$ curl "http://www.rcsb.org/pdb/files/{1ema,1gf1,1g7k}.pdb"
```
### Submitting a job
- Before submitting a job:
	- Locate all your input data in one place on the remote system
	- Create a job script
- Once a job script is submitted, it joins the queue

```bash
# What queues are available?
$ sinf -l
$ qstat -q

# Where are programs installed?
$ /share/apps

# What programs are installed as modules?
$ <module> avail

# How can you load a module?
$ <module> load blast
```

```bash
# Submit a job
$ sbatch <job_script.sh>

# Check when a job will run
$ squeue -start -j <job_id>

# Check status of a job
$ squeue -l -u <user_name>
```

```bash
# Cancel the job
$ scancel <job_id>

# Cancel all jobs
$ scancel -u <username>

# Cancel all pending jobs
$ scancel -t PENDING -u <username>
```
### Writing a SLURM script
```bash
#!/bin/bash

#SBATCH --job-name=<job_name>
#SBATCH --partition <name_of_queue>
#SBATCH --nodes=<no_nodes>
#SBATCH --cpus-per-task=<no_cpus>
#SBATCH --time=<hr:mi:sc>
#SBATCH -o %j.out
#SBATCH -e %j.err
#SBATCH --mail-type=ALL
#SBATCH --mail-user=<email>
#SBATCH --qos comp

cd $SLURM_JOB_ID

<command1>
<command2>
```

- `%j` refers to the job ID
	- `%j.out` and `%j.err` refer to `STDOUT` and `STDERR`
- For jobs that write extensive output, add the following:

```bash
# Copy input files to the scratch disk
rsync -arl * /scratch/$SLURM_JOB_ID

# Move to the scratch folder to run the job
cd /scratch/$SLURM_JOB_ID

# Run the job
<command1>
<command2>

# Move back to the original folder
cd $SLURM_SUBMIT_DIR

# Copy the output files from the scratch disk
rsync -arl /scratch/$SLURM_JOB_ID/* .
```
### Verifying data integrity
- Very large files can often suffer from data integrity issues
	- Since download times are long, network issues such as the connecting dropping can lead to a loss of data
- After downloading, you should use checksums to verify that the downloaded data is intact

> [!definition] Checksums
> - **checksum**: a highly compressed data summary used to verify data was successfully downloaded
> 	- 40 characters in length, given in hexadecimal format (16 character options)
> 	- Checksum algorithms are deterministic, meaning that the same dataset will always return the same value

- MD5 and SHA-1 are commonly used checksum algorithms

> [!process] Verifying data integrity
> 1. Generate checksum values for the original datasets and store them in a text files
> 2. Download the data and the text file with the checksum
> 3. Calculate the checksum values on downloaded data
> 4. Compare the values; a difference indicates corrupted data

```bash
# Calculate an MD5 hash
$ md5sum <source_file> > <output_file>

# Compare MD5 hashes
$ diff <file1> <file2>
```
